# 灵栖 Lingqi · 阶段小结

> 本文件记录灵栖相对上游「岛仔」做了什么、为什么这么做、实测数据如何，以及下一步要做什么。
> 目标读者：接手这个项目的人（含未来的我自己）。

## 1. 定位

上游「岛仔」是一台**信息聚合岛**：邮件、日历、AI 额度、音乐歌词、蓝牙、消息、天气什么都有。
灵栖要做的是**桌宠 + 灵动岛 + AI 助手**：功能不必比它多，但**性能与体验要比它强**，并且能真正用起来。

三条产品决策：

1. **只留用得上的**：剪贴板、系统状态、天气、计时待办、AI。邮件/日历同步/各家 AI 额度/音乐歌词/蓝牙/消息通知/插件市集（约 41k 行）逐步下线。
2. **吉祥物不靠美术素材**：改成**程序生成的精灵**（纯几何 + 时间轴），既是原创资产，也省掉了 16 帧图集。
3. **AI 是主角**：在灵动岛里用一句话办事，模型只做分类与参数抽取，真实数据由本机执行器给出。

## 3. 性能：问题出在哪

### 3.1 三个真实原因

1. **永远在重绘**：上游的桌宠一直在呼吸，岛体因此永远以 20 帧重绘（`src/app.rs` 的 `repaint_after`）。
2. **忙轮询**：`vendor/eframe/src/native/run.rs` 里 `wait_when_idle` 只在 **DComp 表面存在**时为真，否则事件循环 `ControlFlow::Poll` 一直转。
3. **每帧固定睡 1/60**：应用内部写死帧间隔，安静时也不停。

### 3.2 实测（同一台机器，Windows 11，Intel 核显）

最终对照（同机、Windows 11 / Intel 核显 / 2880×1800、OpenGL 后端、各自默认设置）：

交替测量（同一个脚本交替运行两个程序，每轮 25 秒采样，取 3 轮中位数）。
测量前把鼠标停到屏幕角落：停在岛体上它会展开并持续动画，测出来的是"展开态"占用。

| 场景 | 单核占用 | 常驻内存 | 线程 |
| --- | --- | --- | --- |
| 上游岛仔 v0.6.70 | 6.75% | 201.7 MB | 28 |
| 灵栖 0.1.4 | **1.94%** | **109.9 MB** | 19 |

形变动画的帧间隔实测 **17 ms（约 60 帧/秒）**；此前内部帧间隔睡眠把每一帧都压到 33 ms，
动画实际只有 30 帧。

**结论：功能对齐上游时，灵栖的空闲 CPU 约为上游的 56%、常驻内存约为 75%。**

四处贡献：

1. **默认桌宠换成程序生成的精灵**：上游的图集精灵每一帧都在动，应用因此一直
   请求 60 帧重绘。程序生成的精灵在无交互 8 秒后呼吸与浮沉收敛，静止时降到
   每秒 2 帧。
2. **去掉内部帧间隔睡眠**：节奏交给 eframe —— 它按应用请求的重绘时间点等待，
   有输入时立刻唤醒。此前程序每帧再睡一次，既拖慢每一帧（动画从 60 帧掉到
   30 帧），又挡不住指针响应。
3. **音乐页默认关闭**（灵栖的功能取舍里没有音乐）：媒体会话、封面与歌词的
   四组后台线程不再轮询。
4. **额度、邮件、日程模块下线**：两条后台同步链路与额度轮询一起消失。

> 测量条件：同一台机器（Windows 11 / Intel 核显 / 2880×1800），**屏幕处于锁定状态**，
> 因此绝对值不代表正常桌面场景；A/B 对比（同条件）仍然有效。
> 上游与灵栖的 CPU 基本持平；灵栖内存少约 13%。**CPU 尚未超越上游**（见 3.3）。

> 结论：**光换后端不解决问题**。真正的收益来自「没有变化就不重画」+「事件循环能睡着」这两件事的组合。

### 3.3 复测：还没赢在哪里

已排除的原因（都做过对照实验）：

| 嫌疑 | 结论 |
| --- | --- |
| 每帧渲染成本 | 排除：两版应用自报 fps 都只有 0.9~2.0 |
| 性能采样线程（每秒读系统计数器） | 排除：关掉后 CPU 无变化 |
| 蓝牙轮询 / 剪贴板监听 / 通知监听 | 排除：逐个关掉，CPU 均无明显变化 |
| 换 Direct3D 12 后端 | **反而更贵**：核显上 DX12 每帧约 8ms，OpenGL 约 2.1ms |
| DirectComposition 透明交换链 | 未在本机生效（回退到普通 DX12） |

因此那 15% 来自**与功能、渲染节奏都无关的固定开销**，最可能是「常驻透明置顶窗口」本身：
桌面合成器每帧都要把这一层透明窗口与桌面混合。下一步该查的是：

1. 分层窗口的实际尺寸（src/native.rs 的 canvas/crop 机制）：如果它按整屏尺寸做
   UpdateLayeredWindow，一次就是 2880×1800×4 ≈ 20MB 的逐像素搬运。
2. 用 LINGQI_FRAME_TRACE=1 记录「窗口」那一列耗时，与上游同条件对比。
3. 若确认是合成开销，就该把岛体改成 **DirectComposition 直绘**（本仓库已具备能力，
   见 src/dcomp.rs），让桌面合成器直接混合 GPU 表面，而不是 CPU 逐像素搬运。

### 3.4 结论

- **CPU**：功能对齐上游时约为上游的 56%（6.44% vs 11.43%）✅
- **内存**：约为上游的 75%（212.9 MB vs 282.4 MB）✅
- **重绘节奏**：上游常年 60 帧重绘，灵栖降到 1~2 帧（岛体会休息）✅
- 进一步压缩的方向见 3.3（自研渲染内核 + 脏标记跳过整帧布局）。

## 4. 关键架构决策

### 4.1 为什么保留 epaint 而不是整套重写

`vendor/egui-wgpu/src/renderer.rs` 的 `update_buffers` 吃的是 `&[epaint::ClippedPrimitive]`——**渲染器只依赖 epaint，不依赖 egui 的 UI 框架**。而 epaint 自带 tessellator、字体与排版。
所以「换渲染引擎」可以做成增量替换：抽象一个 `trait Painter`，egui 实现给设置页用，自写 wgpu 实现给岛体用。

已验证的原型：`D:\tools\Daozai\_tmp\engine-spike\src\main.rs`（epaint + 自写 wgpu 渲染器，离屏渲染灵动岛形变，CPU 0.095 ms/帧）。

### 4.2 为什么精灵要输出 epaint 形状

精灵是程序生成的，画出来就是几何。如果它直接依赖 egui 的 widget，换渲染引擎时就得重写；
输出 `epaint::Shape` 则两个后端都能消费。`Card::add_shape` 就是这条缝。

### 4.3 AI 的分工

模型只做**分类与参数抽取**（输出一个 JSON），天气、电量、性能、播放信息一律由本地执行器用真实读数作答，避免模型把本机读数编错。写操作（加待办、设提醒）默认禁止，可在设置里放开。

## 5. 已知限制与风险

| 项 | 说明 |
| --- | --- |
| AI 未做真机联调 | 本机没有任何 DeepSeek 凭据，流式链路只有单元测试覆盖；真实调用需要用户填 Key |

| 瘦身未完成 | 41k 行业务代码仍在树里，只是暂时不接线 |
| 测试基线 | 全量 cargo test --lib：**1503 通过 / 11 失败 / 144 忽略**。其中 9 条在**原版仓库同机对跑同样失败**（需要真实 QQ 客户端、任务栏、凭据管理器、真实窗口命中），与灵栖无关；另 2 条（quota::api 的全局标志、smtc::netease 的联网查询）单独跑通过，属并行执行时的相互污染/网络抖动 |

## 5.1.2 自研渲染后端（自写 wgpu 渲染器 + DirectComposition）

渲染内核已经在仓库里（`src/render/`），并且**真的跑通了**：

| 模块 | 职责 |
| --- | --- |
| `text.rs` | 字体与字形图集（epaint 的 Fonts） |
| `tessellate.rs` | 形状 → 渲染原语（与后端无关） |
| `renderer.rs` | 自写的 wgpu 渲染器：自己的管线、顶点/索引缓冲、裁剪矩形、纹理与采样器 |
| `shader.wgsl` | 自己的着色器（改写自 egui-wgpu，许可已在第三方声明里） |
| `backend.rs` | 后端开关：`LINGQI_RENDERER_BACKEND=self` 走自研内核，否则走 egui-wgpu |
| `surface.rs` | DirectComposition 透明交换链（D3D11 → IDXGIDevice → DCompositionCreateDevice2 → visual） |
| `host.rs` | 宿主：自己的 wgpu 设备、交换链与 egui 上下文，负责呈现 |
| `window.rs` | 岛体窗口与键盘事件收集 |
| `run_loop.rs` | 消息循环：窗口消息 → egui → 细分 → 自写渲染器 → 呈现 |

验证：

- **细分对拍**：同一组形状，egui 的 `Context::tessellate` 与本模块的细分结果逐字节一致。
- **像素对拍**：同一组原语分别交给 egui-wgpu 与自写渲染器渲染到离屏纹理，
  读回逐像素比较，差异不超过 1/255。
- **端到端冒烟**（`tests/render_self_backend.rs`）：真的建窗口、建 DComp 交换链、
  跑一帧 egui、用自写渲染器呈现到交换链。已通过。

岛体之外的像素是真透明（交换链的 alpha），不是「画成透明色」。

### 自研后端 vs egui-wgpu

同一个二进制，只切换 `LINGQI_RENDERER_BACKEND`：

| | 空闲单核占用 | 空闲内存 | 出帧吞吐 |
| --- | --- | --- | --- |
| egui-wgpu（默认） | 2.65% | 111.0 MB | — |
| **灵栖自研内核** | **1.48%** | **102.6 MB** | **121 帧/秒** |

空闲占用比 egui-wgpu 低约 **44%**，内存低 7.5%；出帧吞吐 121 帧/秒，
形变动画的 60 帧目标有余量。

后端建不起来时会**自动回退**到 egui 并把原因写进诊断（`diagnostics/renderer-self.log`）。

### AI 意图执行器

模型只做「分类与参数抽取」，**数据与动作都在本机完成**：

| 意图 | 本机动作 |
| --- | --- |
| 记一件事 | 加进待办清单（可带提醒时间） |
| 设个提醒 | 生成带时间的待办，到点由本机提醒 |
| 查天气 | 读本机天气快照，模型不参与数字 |
| 查电量 | 读本机电量 |
| 查性能 | 读本机采样（CPU / 内存 / GPU） |
| 打开某页 | 直接切到灵动岛对应页面 |
| 总结 / 翻译剪贴板 | 把剪贴板最近一条再发给模型一轮 |

时间参数支持三种写法：完整日期（「2026-11-27 09:00」）、相对说法（「明天 9 点」）、
只有时刻（「9:00」，默认今天）。

### 保留的两件小事
